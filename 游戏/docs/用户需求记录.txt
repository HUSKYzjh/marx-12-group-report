R002｜区分使用价值与交换价值，探讨新科技的两种价值
提出日期：2026-10-11
用户原话：要求在游戏合适部分区分使用价值和交换价值，探讨新科技的使用价值和交换价值。
状态：已实现（2026-10-12逐项验收；下方早期记录保留当时状态）

用户明确要求
1. 在游戏合适的部分区分“使用价值”和“交换价值”。
2. 将这一区分用于讨论新科技，而非仅解释普通商品。

实施建议（尚未作为最终方案落实）
1. 在换炉或新机器场景先建立区分，在 AI／自动化相关场景回扣。
2. 使用价值侧重具体用途：技术能满足什么需要，能否节省劳动、提高质量、减少资源耗用。
3. 交换价值侧重商品交换关系：以可交易的设备、软件或技术服务为对象，讨论它能与什么、按什么比例交换，并借售价观察其货币表现。
4. 通过同一技术的对照追问：它很有用，是否就一定能卖出高价？价格降低，是否意味着它不再有用？谁能使用它，谁获得销售收入或节省成本的收益？
5. 可比较技术独占与技术普及的情形，但具体价格、效果和收益须按明确条件设定，不预写必然结局。

实现与验收要点（用于后续检查）
1. 玩家能够用同一设备或技术服务，分别说出其具体用途与交换表现。
2. 价格、销售收入、成本节约和企业利润分别说明，不统称“交换价值”。
3. 不把使用价值直接等同于“社会善”，也不把交换价值等同于“贪婪”；有用与否、满足谁的需要及后果须结合具体情境。
4. 明确讨论对象：设备、软件或服务的交换表现，与采用技术后所生产商品的交换表现，不能混在一起。
5. 若进一步涉及马克思的价值理论，区分使用价值、价值、交换价值和价格，并核对原典；不把教学数值或视频概括当作严格定义。
6. 保留现有游戏流程与存档；是否新增互动、如何安排入口，在实际设计时依据现有场景确定。

当前落实情况：已登记需求及实施建议；本次尚未修改游戏中的使用价值／交换价值内容。

R003｜比较 C-M-C1 与 M-C-M1，探讨新技术带来的改变
提出日期：2026-10-11
用户原话：要求游戏探讨 C-M-C1  M-C-M1，和新技术造成的新改变。
状态：已实现（2026-10-12逐项验收；下方早期记录保留当时状态）
关联需求：R002（使用价值与交换价值）。

用户明确要求
1. 游戏探讨 C-M-C1 与 M-C-M1 两种运动。
2. 将两者与新技术造成的变化联系起来，不能只展示抽象公式。

记号说明与概念处理（作为后续设计依据，正式文案需核对原典）
1. C 表示商品，M 表示货币；保留用户原话中的 C1、M1，展示时解释其含义。
2. C-M-C1：卖出一种商品，取得货币，再购买另一种满足需要的商品；重点是不同使用价值之间的转换。通常写作 C-M-C，C1 在此用于区分终点商品，不表示其价值必然增加。
3. M-C-M1：预付货币，购买商品，再回到货币；作为资本一般公式通常写作 M-C-M′，以 M′＝M＋ΔM 表示增殖目标。实际经营可能亏损，不预设每次都实现增殖。
4. 两者区别要落实到运动的目的、起点与终点，不能简单变成“好人消费、坏人赚钱”的角色划分。
5. 在生产企业案例中展开中间过程：购买生产资料与劳动力 → 生产 → 出售产品。不能把资本增殖仅解释成低买高卖，也不能让技术在账本中凭空生成货币。

实施建议（尚未作为最终方案落实）
1. 延续面包店场景，用两条可追踪的商品与货币路径，并排呈现为了取得所需商品的交换和以增殖为目标的资本运动。
2. 若使用雇员情境，明确其出售的是劳动力、取得工资后购买生活资料，不画成雇员直接拥有并出售面包店的产品。
3. 对比同一新机器的两类问题：能多做多少、节省多少劳动、满足哪些需要；需要预付多少资金、产品能否卖出、最终收回多少货币。
4. 技术更新后的改变可包括生产时间、产量、单位成本、售价、岗位与工资、购买能力和销售实现；各项变化按具体条件呈现，不假设同步同向变化。
5. 比较技术独占与普及后的竞争条件，以及软件、AI服务通过订阅、授权等方式交易的情形；技术效果与所有权、使用权限、收费规则分别说明。
6. 与 R002 回扣：更强的实用能力为何不必然带来更高售价或更多利润？增殖目标又怎样影响技术被开发、采用和使用的方向？

实现与验收要点（用于后续检查）
1. 玩家能区分“为买而卖”与“为卖而买”，并说出终点分别是什么。
2. 清楚区分 C1 的商品差别与 M1／M′ 的货币增殖，不将两个下标解释成同一种增长。
3. 对比相同技术在不同需求、竞争或分配条件下的结果；至少允许技术有用但销售不佳，以及技术改进且销售实现的情形。
4. 预付资金、销售收入、剩余库存、成本与利润分别展示；库存和产能不能直接算作已实现货币收益。
5. 教学经营利润不直接等同于马克思的剩余价值量；涉及增殖来源时核对理论，不以简化账本替代理论证明。
6. 本要求与 R002 共同安排入口，避免重复讲解；保留现有存档与各实验账本的边界。

当前落实情况：已追加需求、记号说明与实施建议；尚未改动游戏运行内容。

R004｜以比特币作为两种运动与技术变化的案例
提出日期：2026-10-11
用户原话：你可以以比特币举例。
状态：已实现
关联需求：R002、R003。
要求性质：用户允许采用的具体案例；不据此将整个游戏改成比特币交易游戏。

案例设计建议（尚未实现）
1. 支付用途：设定交易双方愿意接受比特币，人物出售商品取得比特币，再购买所需商品。此处比特币在场景中充当交换媒介，关注终点的生活需要，对应 C-M-C 的运动目的；不宣称比特币在所有场景和理论中都等同于货币。

3. 两种目的对照：同一技术既可被用于支付，也可成为转售获利的对象；参与者的目的和交易条件需要分别交代，允许混合动机。

概念与验收要点
1. 资产转售的差价不能直接当成全社会新增财富或生产中创造的剩余价值；单次交易路径也不能解释资本增殖的全部来源。
2. 不将“比特币网络”“持有的比特币单位”“挖矿设备和服务”视为同一分析对象。
3. 不预设升值，不把虚构收益写成投资建议或实际市场事实。
4. 比特币的货币属性、商品属性与马克思价值理论中的定位，正式文案须注明分析口径，不能伪装成无争议结论。

已核对资料：Satoshi Nakamoto, Bitcoin: A Peer-to-Peer Electronic Cash System，摘要、引言与第6节；https://bitcoin.org/bitcoin.pdf。
资料用途：核对原始设计中的点对点电子支付目标，以及算力、电力、发行激励和交易费；不用于证明当前市场表现或比特币的理论分类。

R006｜体现可变资本、不变资本与技术进步之间的关系
提出日期：2026-10-11
用户原话：文稿中有部分提到可变资本，请整理。这部分涉及到技术进步，我需要在游戏中体现出啦。
状态：已实现（2026-10-12逐项验收；下方早期记录保留当时状态）
关联需求：R002、R003、R005；衔接现有换炉、竞争、工资分配与自动化场景。

文稿整理与原典核对
1. 30:11—30:38：作者引入利润率下降，联系资本主义内部矛盾。
2. 32:25—32:53：作者讲资本分类、竞争推动技术进步与机器替代劳动。
3. 33:22—33:48：作者讲机械化与加强劳动控制可以并存，以及岗位与技能结构变化。
4. 34:15—34:43：作者联系扩产、资源压力、利润和市场；这里把多种机制串联，设计时需要分别处理。

必须修正的概念
1. 可变资本 v：资本中用于购买劳动力的部分，通常以工资支付表现；不能把劳动者本人称为一笔资本，也不等于劳动力这一能力本身。
2. 不变资本 c：用于生产资料的资本，如机器、原料、生产中耗用的燃料；在马克思价值理论中，其价值随生产耗用转移到产品中，不在该生产过程中自行创造剩余价值。
3. “可变”不是指工资经常变动或员工容易被替换；“不变”不是指设备价格、原料用量或技术永远不变。分类依据是它们在价值增殖中的作用。
4. 不变／可变，与固定／流动，是两种分类。机器通常是不变资本中的固定部分，原料是不变资本中的流动部分；购买劳动力的资本属于流动部分。文稿32:25的“固定资本和可变资本”混淆分类，不能照搬。
5. 在马克思理论中，机器能提高实物生产效率，但不能据此认定机器在其使用过程中独立创造新增价值；使用价值、价值量、价格与经营利润须区分。
6. 文稿称机械化与加强劳动剥削并存是“马克思没想到”，不准确。《资本论》机器和大工业章节已讨论加长工作日、劳动强化和机器排挤工人的关系。

作者论述可保留的核心问题
竞争促使企业采用更高效的技术；单个企业可能因此获得成本优势。但技术扩散会改变行业条件，技术提高的生产能力如何转化为销售、收益、工时和就业，需要进一步解释，不能由机器效率自动推出。

建议的游戏体验（尚未实现）
1. 同一面包店换炉前后：在相同产品质量和观察期下，比较人数、每人工时、任务分配、实物产量、原料耗用与设备支出。
2. 单店先采用：只有本店装快炉，在明确售价、需求和购机成本的条件下观察单位成本及经营结果，表现采用技术的个别激励。
3. 邻店跟进：同行采用后，分别改变价格和订单条件，观察原有优势能否维持；不能将同行跟进直接写成利润必降。
4. 同一技术的安排对照：保留人数并约定缩时不减薪；维持工时并扩产；减少某些岗位并显示失去的工资收入；调整任务并培训。费用、产量和可行性分别计算，不把所有方案预设为等成本。
5. 机器与劳动控制并存：展示机械化不自动让留下的人轻松；可另设提高工作节奏或延长工时的方案，并呈现劳动者的时间与负担。效率与劳动强度不是同一变量，不能用一条速度滑块代替两者。
6. 订单与分配反馈：减员、工资或工时变化只有通过明确的家庭收入与消费规则才影响订单；保留需求扩大、工资提高或缩时获益的反例。
7. AI衔接：按具体任务区分替代、辅助与新增核对工作，纳入培训、维护及人工收尾；不把任务自动化比例直接当作岗位裁撤比例。

利润率的可选理论说明
1. 在明确采用简化价值模型、忽略周转差异等条件时，用 p′＝s／(c＋v)，并说明 s 为剩余价值，s／v 为剩余价值率；二者不是同一比率。
2. 若 s／v 不变，c／v 上升会使该模型中的利润率下降；这是有条件的推论，不是从“换了机器”就能直接得出的现实结论。
3. 技术进步也可能使生产资料便宜、改变剩余价值率和周转等条件；马克思本人讨论了反作用因素。利润率下降与利润总量下降分别说明。
4. 不将产品单位利润、营业利润率和上述价值利润率混用；现有现金经营账本不直接填作 c、v、s。
5. 设备购入支出、设备存量和当期折旧分别展示；不能既把购机款全部计入当期费用，又重复扣同一部分折旧。理论分母中的预付资本与当期消耗量也需分别界定。

实现与验收要点
1. 玩家能解释同一台机器为何可能带来扩产、岗位变化或缩短工时等不同结果，以及这些结果由什么条件决定。
2. 人数、工资总额、单人工资、工时、产量与销售分别追踪；资本构成变化不能仅用“机器图标多、工人图标少”证明。
3. 允许用工相对减少而企业扩张后绝对人数增加的情形，不预设技术进步必然减少全社会就业。
4. 不写成“机器越多 → 新增价值越多”，也不写成“机器越多 → 必然立即无利润或崩溃”。
5. 区分生产能力、商品价值和销售实现三个层面，不把积压等同于利润率趋向下降规律。
6. 使用现有素材与相近场景，保持模型、存档与独立实验账本边界；新增内容是否需要独立入口在实现时确定。

用户补充的核心方向
游戏须讨论消费主义、消费的信贷化与货币金融危机之间的联系，而不止停留在机器扩产与商品积压。

建议的机制与体验（尚未实现）
1. 在技术提高产能的背景下，分别观察消费愿望、家庭收入和可支付购买；广告或消费愿望增加不自动产生支付能力，收入变化也不是技术的唯一后果。
2. 家庭获得消费贷款或分期额度后，本期可以增加购买，企业销售暂时改善；同步展示家庭负债、期限、利息与后续还款，不能把贷款当作工资收入。

4. 若偿债压力增加，家庭可能减少其他支出或违约；违约又可能让持有债权的机构承受损失。在明确资本、融资与放贷规则后，观察损失如何影响后续信用供给。
5. 信贷收紧可能影响企业融资、订单、生产和就业，再影响家庭收入；逐笔展示联系，不用“一家违约，所有银行立刻倒闭”的固定剧情。
6. 用并排路径比较主要依靠收入增长、主要依靠新增借债、以及两者结合的消费扩张；同样的当期销量可以伴随不同的债务与后续支付负担。
7. 与 R005 衔接时，区分消费贷款和住房抵押贷款；住房贷款还涉及房价、抵押物及再融资条件，不能将2008年危机简化成消费者买得太多。

设计追问
技术使社会更能生产，为什么满足需要可能仍依赖家庭增加负债？信贷是在帮助跨期安排支出，还是在特定条件下延后暴露收入与销售的困难？危机发生时，债务、失业和救助成本由谁承担？

概念与验收要点
1. 消费主义、消费增长、信贷扩张和金融危机分别解释，不能用“消费主义 → 必然金融危机”作为固定规律。
2. 区分有需求、能付款和能持续偿债；借款、收入、本金偿还、利息支付与债务余额分别记账。
3. 明确贷款来自既有资金转贷还是银行创造存款的模型；若模拟后者，贷款资产与存款负债同时记录，不能把之前有限现金模型直接套用。
4. 债权损失、资产价格下跌、资金流动性不足与资不抵债分别呈现；不能把金融资产价值下降直接写成等额现金凭空消失。
5. 信贷有可能缓解短期困难，也有可能在条件变化时放大风险；保留正常偿还与风险缓解的情形，不以玩家必须破产作为完成条件。
6. 与现有消费／借款实验复用时先核对账本和规则；独立假想实验不能静默改变主线贷款、存款与存档。

已核对的相关观点（教学概括，不是逐字引文）
依据兰德《Teleoplexy: Notes on Acceleration》（2014）相关段落：
1. 技术与资本积累相互强化：再投资改善生产装置，商业化与工业化形成正反馈；“加速”不只是机器运行得更快（§00—02）。
2. 手段可能变成目的：原本服务人的工具，在自我生产和扩张的回路中转而服务系统自身的延续（§07—09）。
3. 资本自动化与自主化：他设想资本流向机器的自动化、自我复制与改进，并质疑既有产权与主体概念能否解释这些变化（§14、17）。这不是证明资本已有意识。
4. 不以人类利益为必然终点：从上述论述可以概括出，技术资本的扩张不保证服从人的需要；这一概括不能直接推成“所有劳动都可替代”或“人类必然灭绝”。
5. 区分加速主义内部立场：斯尔尼切克与威廉姆斯的2013年宣言主张改造技术基础设施、服务共同目的，并明确技术本身不足以带来解放；不能与兰德合成同一主张。

适合游戏的实施建议（尚未实现）
1. 在自动化或竞争实验后，追问“究竟谁在加速？”。把企业竞争、再投资和技术采用连成可观察的回路；每一步仍受订单、资金、设备成本和现实可行性约束，不凭空保证无限增长。
2. 用相同技术能力对照不同目标：提高产量与回款、缩短有薪工时、满足尚未满足的需要。分别呈现收入、时间、供给和决定权，不用效率一个数字代替全部结果。
3. 区分三个层面：机器接手某些任务；竞争压缩个人或企业的选择；机器取得独立设定目标的能力。前两者不自动证明第三者。
4. 将兰德视角作为可比较、可质疑的思想立场。核心追问可写成：“机器接下工作之后，增长服务谁？人还能改变目标吗？”不要把该句标作兰德引文。
5. 延续现有精简文案原则：主界面留问题与可见后果，理论、原文、推测边界按需展开，不强制先读长篇说明。

概念与验收建议
1. 玩家能区别“减少对某些人类劳动的依赖”与“脱离所有人类及物质条件”；研发、维护、能源、原料、需求等条件须按具体模型交代。
2. 区分技术自主执行与社会意义上的自主权，不把自动排班等同于机器有自我意识，也不把现实AI拟人化为必然觉醒的主体。
3. 明示哪些是兰德的哲学论述、视频作者的概括、游戏假设和玩家观察；不把技术决定论或灭绝叙事写成通关结论。

# Codex游戏开发流程

2026-10-02。本文件把官方OpenAI文档中的游戏开发经验转成适用于本作的工作方法：先把核心操作做成可验证的小场景，再接故事、美术、角色和课堂统计。本轮完成研究与流程设计，不代表这些实现步骤已执行。

## 官方案例说明了什么

OpenAI的[Codex Pet Arena案例](https://developers.openai.com/showcase/codex-pet-arena)记录了先用占位形状调好移动与收集、再增加对手与规则、机制稳定后换正式角色美术，最后检查键盘、触控和性能的过程。这是一个具体项目的迭代记录，不是所有游戏必须照抄的模板。

2026-09-04的[Building games with Astra](https://developers.openai.com/blog/how-to-build-games-with-astra)强调从可体验的约束出发，并给开发代理提供可重复场景、运行状态和浏览器测试；直接载入场景的检查与真实操作旅程的测试分开。作者还明确区分软件渲染环境的测量与真实硬件表现。

本作的推导是：先验证一个认识动作是否成立，让Codex能重现错误，但仍由人判断叙事是否清楚、有趣、有感染力。该案例的Three.js、WebGPU和空间生成并非我们的需求；无需因此更换现有二维网页技术栈，也不要求改用案例中的模型。

## 本作的开发闭环

1. 写出可观察的体验目标，例如“机器转快后，我看见产量增加，但合同工资不变”，而不是“页面要高级”。把权限、基准和反例一起给出。
2. 用现有元素或占位块做一个灰盒小场景。先能操作、看后果和重跑，不先补全所有插画与文章。
3. 把经济结算放在纯函数中，画面读取结果。对话、动画、统计请求不能各自修改余额。
4. 编写确定性场景夹具和模型测试，再用真实按钮从头走到结果。测试场景能帮助复现，但不能替代完整操作。
5. 接入资产库里有明确用途的图片与组件；检查裁片、小尺寸辨识、加载失败和非颜色提示。
6. 试玩观察玩家卡在哪里、期待什么、看懂什么。每次只调整一个问题，修复后重跑原场景及相关路线。
7. 保存实际验收记录：代码版本、操作路径、截图对应状态、结果、未测项。只有达到阶段门槛才扩展角色或接外部服务。

开发中先保留已有改动，不自动提交、推送或发布；不把真实账户凭证写入客户端。场景检查与内容审查分别记录，程序算对不能证明政治经济学解释正确。

## 每次给Codex的任务包

每个任务只交一个可验收的认识动作，包含问题、角色、允许操作、模型基准、素材输入、画面后果、反例、不能推出什么、需要跑的检查和交付路径。本文任务模板是本项目建议，不是已执行命令。

### 示例任务

实现工厂劳动者的机器与合同场景。先检查现有M1函数和测试，保留用户已有改动。采用现有新旧机器、人物、金币和四关系符号。玩家先预测，再切到新机；工资按每人每轮计，不自动加薪或缩时。明确标H教学模型和全部售出假设。动画只显示已结算结果，连续点击不重复生产。提供原基准重跑、跳过和键盘操作。完成模型测试与320／390 CSS像素下的真实按钮流程，记录未测项，不部署、不新增AI服务、不修改其他经济模型。

另一类任务是明确的研究任务：“只评审这一幕的因果解释，不修改运行代码；指出它能支持和不能支持的结论。”诊断、审查与实现授权不能混在一句模糊的“优化全部”中。

## 代码组织建议

这些是拟实现边界，不要求今天搬动现有文件。

| 层 | 责任 | 禁止事项 |
| --- | --- | --- |
| 场景配置 | 角色位置、模块来源、步骤、文案、动作与许可 | 用P编号强行串成35步，或给未开放角色假入口 |
| 模型与快照 | 确定性结果、单位、基准、输入与版本 | 将M1、M2、家庭债和公共预算混成一个余额 |
| 交互控制 | 预测、提交、揭示、对照、重跑、恢复 | 动画重播重新扣款；看资料自动完成其他角色 |
| 画面组件 | 人物、机器、托盘、时间条、关系图和证据层 | 从DOM倒推经济状态；图片内固化数字和长文字 |
| 内容与证据 | 原句出处、资料冻结日期、研究对象与结论边界 | 以教学模拟代替现实研究，或用来源标题推断效果 |
| 统计适配 | 符合契约的首次事件与同条件汇总 | 失败阻塞剧情，重复重跑计为新人，向前端暴露密钥 |

现有React与CSS先行。只有文本分支维护确实困难才试inkjs；只有现有图表无法清晰表达才试新库。Codex开发本作不等于玩家运行时必须调用AI。首版剧情与模型应能离线独立运行。

## 复现与测试设计

拟提供的命名夹具至少有：旧机、新机同合同、加薪对照、保薪缩时、市场需求24与32、回款延迟、延迟但有缓冲。夹具包含模型和基准版本，不写成已经存在的测试接口。

测试模式可暴露只读的场景ID、角色、步骤、快照、已提交动作与素材加载状态；禁止导出私人数据或服务密钥。正式课堂入口不开放任意改余额的调试按钮。真实旅程测试必须用按钮完成预测、选择、揭示和重跑，而不是直接把页面设成最终状态后截图。

| 检查层 | 验收内容 | 不能代替什么 |
| --- | --- | --- |
| 模型 | 已定义公式、守恒、库存、到期债务、缓冲来源、相同输入相同输出 | 现实经济因果与完整宏观预测 |
| 状态 | 双击、重跑、返回、旧进度迁移、角色切换与未知值 | 手感、说明是否容易理解 |
| 浏览器 | 逐幕实际点击、键盘、弹层焦点、无横向溢出、图片失败、减少动态 | 真实手机、微信内置浏览器与教室网络 |
| 实机与试玩 | 触控辨识、投影可读、扫码、离线恢复、玩家复述与退出点 | 全国代表性意见或学习因果效果估计 |
| 内容 | 马哲定义、角色权限、国家背景、研究口径和出处 | 页面实现、授权批准 |

本地已有 `npm test` 与美术资源核对脚本；浏览器全路线和真实手机验收是后续实施任务，本轮不称其通过。性能阈值应先测首屏资源与目标手机，再定预算，不能拿源文件总字节或别人的帧率证明本作不卡。

## 实施批次

第一批：序章、劳动者前两节点及独立危机实验；危机入口标独立示例，不跳过中间逻辑冒充完整角色路线。第二批：完整劳动者和生产企业路线，补齐需求与支付的承接。第三批：其他角色及历史三图；公共职务角色只使用资本主义国家背景，中国在共同研究结尾分析。第四批：课堂汇总、公网入口与二维码，再考虑教师导出及可选AI解释。

每批先检查现有成果再续做，不能以“有清单、有测试、有截图”直接宣告完成。完整课堂发布需要玩法、内容、素材授权、数据安全和实际网络共同验收。本轮不安装技能或插件，不启用并行代理或定时任务，不开通API服务。

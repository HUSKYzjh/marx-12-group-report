## 核心方法

原作先让玩家行动，再反馈；同一组人物和装置留下，只改变一个条件，早先的结论随后遇到反例。复杂参数最后才在沙盒集中开放。我们据此组织序章，不将合作／欺骗的收益矩阵用作政治经济学模型。

源文件与正文已逐章对照。浏览器实际观察包括开场、单次对局、早前第一位重复对手和部分竞赛；本轮再次观察首个选择的反馈。原作浏览器连接中断，未完整通关演化、误操作和沙盒。以下设计是本作的推导，不代表 Nicky Case 的经济学观点。

## 当前序章

| 环节 | 操作与可见变化 | 要建立的理解 |
| --- | --- | --- |
| 开场 | 人物与生产工具穿插的上下两条链、中央标题、一个开始按钮；划痕遮罩进入分账 | 先让人看见机器与生产，进入故事 |
| 分一笔钱 | 一家公司，±10 个百分点；十份钱移动，双方五档相反表情 | 看见分配选择；这一笔不等于全部工资或营业收入 |
| 谁来买 | 同一个工人留下，钱移动到他身边；比较 20%／80%，可还原 | 工人也是其他公司的顾客；只比较这一笔购买能力，不预测销量 |
| 怎么生产 | 原料、零件、加工、运输连到机器；暂停供货时人物淡下、断线、产品未完成；可恢复 | 生产依赖社会分工；本例假设没有备用供货 |
| 谁作主 | 四个工序与机器留下，老板和钥匙加入 | 参与生产与拥有生产资料有区别 |
| 命名关系 | 保留场景，正式定义出现一次 | 生产社会化与生产资料资本主义私人占有之间的矛盾 |
| 煤矿父女 | 划痕转场；三组指定对白逐组或一次呈现 | 独立改编寓言，不归因于玩家的分账选择 |
| 换个位置 | 一次选择工人或老板，直接进入已有新机器片段 | 从新位置继续观察 |

公司切换和其他关系标识在说明中，主线不用完成四次同类分账。煤矿对白之后不追加总结。AI、危机、选举及研究证据留在后段。

## 实际底座与边界

隔离 iframe 内运行原版 Slideshow、TextBox、helpers、Pixi、Tween、MinPubSub；人物采用 IteratedPeep 分层构造，开场使用 SplashPeep／SplashEdge。原文件未改写，来源与许可见 [CREDITS](../CREDITS.md) 和 `vendor/ncase-trust/provenance.json`。

React 提供确定性状态、独立经济模型和本机保存；运行器呈现画面。普通切幕保留一个 Stage 和 13 个语义固定的人物，已有工人移动、新人物淡入、连线展开。小步文字淡出再接入，开场到分账、定义到寓言采用原作 scratch 图集。未导入原 Scratcher、Q、音效或 PD 规则。

覆盖期间阻止输入穿透，减少动态效果时直接呈现同一状态。20%／80% 是独立假设，不覆盖个人分法；供货暂停不计算收入、失业或破产。序章比例与正式机器账本分开。

共同工序是社会化分工的入门展示，钥匙是产权示意。收入改善、参与治理与占有关系不能混同。资本主义国家的公共支出不自动改变国家性质；社会主义中国的基本制度与具体企业问题分别分析，中国体制不放入资本主义政府角色。

## 原作怎样组织画面

[main.js](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/main.js)分别加载文本与资源，再创建场景和章节导航。[Slideshow.js](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/core/Slideshow.js)管理场景进入、离开、跳转及带标识的对象；推进时不是默认清空全部对象，因此同一台机器和人物可以留下，只改变提问与解释。跳章则另有重设与进入逻辑。

原作使用居中的舞台，文字主要在动作上方和下方，人物、机器、筹码成为主体。界面没有同时铺满知识卡片。按钮和说明随阶段出现；其意义来自玩家刚做过的选择，而非首页就交代全部规则。新版借鉴这种层次，但不用固定宽画布整体缩小来处理手机。

原作使用 PixiJS 渲染人物和模拟，DOM 呈现按钮与文字，Tween 组织动作，发布订阅连接阶段事件；这些依赖可从 [README](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/README.md)核对。这是其历史实现，不构成我们迁入同版本旧引擎的理由。

## 图集并不是一排完整人物

[Iterated.js](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/sims/Iterated.js)将身体、帽子、脸和眉毛装在同一人物容器中，使用一致的定位与缩放。[helpers.js](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/lib/helpers.js)依据图集帧名构造动画对象。原作还把眨眼、走动、投币、表情反应、回位和收益表现串起来，最后才结束本轮。

新版已按此方式装配原始身体、帽子、眼睛、表情与眉毛，而非重新绘制几何五官覆盖原图。中性眼睛采用1帧，眨眼采用2帧；轻微正负反应用4、5帧眉毛，夸张反应用8、9帧脸。原作这些帧属于具体收益反应，本作重新用于分配感受，所以不继承原来的策略身份或道德判断。不用反派大笑或眩晕帧把资本所有者画成天生恶人。新增手臂姿态由本作绘制，必须与原图层来源分开说明。

分配比例决定表情强度，场景阶段决定注意方向；镜头拉远不能自动制造悲伤、失业或危机。减少动态效果时仍显示相同数值与状态，动画不负责经济结算。

## 叙事是怎样逐步扩大问题的

[单次对局](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/1_Slides_OneOff.js)先给具体选择，再依据选择回应，随后换一个条件追问。[重复对局](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/2_Slides_Iterated.js)让玩家先与不同对手交手，之后才解释其规则，而不是先背五种性格定义。

[竞赛](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/3_Slides_Tournament.js)先让玩家预测，再扩大到群体；[演化](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/4_Slides_Evolution.js)逐步开放比赛、淘汰与补充，而不是直接播放结论。[信任条件](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/5_Slides_Distrust.js)和[误操作](https://github.com/ncase/trust/blob/6ec45d73befdb922bd40654dd1c1c903a953562f/js/slides/6_Slides_Noise.js)又改变互动条件，修正玩家早先形成的判断。

据此，我们采用“行动—看后果—追问—只换一个条件—再看后果”的节奏。不是每幕都加一道选择题；操作应从分配、预测、排班变成封存排产、追踪回款与检查权限。问题扩大时保留熟悉对象，让概念成为对亲眼所见关系的命名。

## 新版已经落实的部分

| 环节 | 可见动作 | 认识与边界 |
| --- | --- | --- |
| 一家公司 | 加减分配，工人和老板分别经过五档表情 | 方案总额固定；不是全部工资，也不是幸福测量 |
| 可选换公司 | 说明内切换，四家公司各记自己的分法；主线不要求轮流完成 | 不把所有老板写成同一个减薪脚本 |
| 看联系 | 人物从单厂移动到全景，点工人看可能购买的联系 | 关系不是已经发生的订单，不用比例猜销量 |
| 换关系 | 主线依次看共同条件和产权；其他关系按需展开 | 购物、协作、产权、安排与分配不能混成一条箭头 |
| 看区别 | 保留公司与机器，再显示一次基本矛盾的定义 | 分钱不同不等于产权改变；消费不足不是定义本身 |
| 父女结尾 | 用户指定对白逐组或一次呈现 | 独立改编故事，不强行说是玩家造成的失业 |
| 新机器片段 | 依次预测，再换机；单独比较加薪与保薪缩时 | 同一M1基准；工人观察条件，不拥有单方修改合同的权限 |

画面去掉卡片外框、阴影、仪表盘式色块，放大原人物，采用白底、少量帽子与产品颜色、原手绘按钮。支持 View Transitions 的浏览器以稳定人物标识连接单厂与全景；不支持时直接显示同样的下一状态。主线上只突出一个问题，不把源码研究变成必读说明。

## 本作的底层分工

保留 React 与 TypeScript。场景状态由确定性 reducer 更新，画面只读取状态；表情由比例派生，动画不增加金币。序章定性分配与正式工厂账本相互隔离。新机器实验使用已有 factoryAccount，不另造一套工资或利润公式。原作的旧 PixiJS、音效、字体和合作／欺骗收益规则没有整体迁入。

新机器的三次预测只记录预期，不改变结果或生成成绩。全部预测路径都落在同一个新机基准；加薪、缩时对照分别恢复该基准，不累加。两个入口分别保存本地片段进度，换视角不再生产或领取一份收入。完整七角色路线、课堂真实汇总和公网扫码尚未完成。

## 下一批设计约束

接下来优先做工作日安排，再做两厂封存排产与需求充足的反例，最后接一笔回款的传导。每次只新增一个约束，先发生后解释。需求压力、债务、外贸与政策案例不能全部挤进同一屏，更不能沿预设路径自动崩溃。AI仍留到后段，在玩家认识机器、合同、协作与控制之后出现。

课堂人数只在提交选择之后显示，同班次、同版本、同条件分别汇总；离线没有统计就明确没有，不用演示数字制造共识。古文保留已有名篇登记与出处，不把引句当理论证据。现实研究、教学模型和本文的设计推导继续分开。
